# Kamerton — правила для сессий и агентов

Что это: микшер громкости в трее для Windows 10/11, аналог EarTrumpet (Rust, egui, набор Anvil).
Состояние и долги владельца — [HANDOFF.md](HANDOFF.md); замысел и этапы — [SPEC.md](SPEC.md);
документация того, что есть сейчас, — [docs/README.md](docs/README.md); работа идёт через OpenSpec
(`openspec/changes/<имя>`). Весь текст пользователю — по-русски; тексты в интерфейсе — RU/EN,
светлая и тёмная тема.

## Интерфейс

- Любая работа с видом — по [docs/ui-guideline.md](docs/ui-guideline.md); новое правило — туда же в том же шаге.
- Цвета, шрифты, кнопки — только из `anvil-ui` (тег `kit-v*` в `Cargo.toml`); своих hex нет.

## Звук Windows

- Недокументированные API (`IPolicyConfig`, `IAudioPolicyConfigFactory`) — только в `src/audio/policy.rs`;
  сбой там отключает свою функцию, а не программу.
- Живые проверки не меняют устройство по умолчанию, маршруты и громкость программ пользователя без
  команды владельца; что тронули — вернуть.

## Общие скрипты

- Готовые помощники — `E:\dev_personal\tools\` (оглавление `README.md` там): `patch.py`, `checks.py`,
  `bump_version.py` и др. Скрипты самого проекта — в `scripts/`.

## Диски

- Только **E:** — репозиторий, worktrees, `target`, логи. Общая папка — `E:\dev_personal\kamerton-scratch`
  (отчёты агентов — `reports\`, сборка судей — `target-judge\`, снимки и журналы проверок). D: запрещён.

## Сборка и проверка (на ПК; CI — по правилу ниже)

- По ходу — `cargo check -j 4`, вывод в файл.
- Перед сдачей один раз: `python E:/dev_personal/tools/checks.py --repo . -j 4 fmt test clippy`
  (программа только под Windows — шаг `zig` не нужен).
- Результат — по коду выхода; вывод в файл, в разговор хвост.
- Живая проверка окна: запустить `target\debug\kamerton.exe`, снять экран; **курсор пользователя не двигать**.

## Сборка на GitHub

- После каждой новой версии (подъём X.Y.Z) — собрать билд на GitHub: запустить CI кнопкой
  (`workflow_dispatch`, скил `github-ci`, помощник `ghci.py`), дождаться результата и назвать его
  в отчёте с минутами прогона. Перед кнопкой — те же проверки на ПК. Владелец, 24.10.2026.
  Автоматом — только в открытых репозиториях (Kamerton открытый); в закрытых сборка на GitHub
  только по команде владельца. В остальных случаях CI тоже по слову владельца.

## Работа агентов

- Исполнитель — свой worktree, коммиты по-английски в своей ветке, не пушит; называет ветку и хэш.
- Судья и сверщик документации — без worktree, читают `main`, собирают в `target-judge`.
- Отчёт — до ~25 строк, подробности в `kamerton-scratch\reports\<имя>.md`.
- Версию агент не меняет, если задача этого прямо не требует.
