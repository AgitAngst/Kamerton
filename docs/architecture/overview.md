# Как устроено

## Части

| Файл | Что делает |
|---|---|
| `src/main.rs` | разбор ключей: без ключей — трей, `--flyout` — окно микшера, остальное — консольные режимы |
| `src/audio/mod.rs` | `Audio`, `Control`: поток звука, каналы команд и событий, склейка меток |
| `src/audio/win.rs` | COM: Core Audio, подписки на события Windows, слежение за процессами |
| `src/audio/model.rs` | модель без COM: устройства, программы, события, разница снимков, шаг громкости |
| `src/audio/policy.rs` | недокументированное: устройство по умолчанию (`IPolicyConfig`), закрепление программ (`AudioPolicyConfig`) |
| `src/config.rs` | настройки: `%APPDATA%\Kamerton\settings.txt` (вид окна, горячие клавиши) |
| `src/profiles.rs` | профили, память громкости, правило подключения — решения чистыми функциями |
| `src/hotkeys.rs` | сочетания: текст ↔ модификаторы и код клавиши Windows, действия, следующее устройство |
| `src/tray.rs` | поток трея: значок (знак или колонка, кадры по таймеру), подсказка, щелчок, меню, хук колеса |
| `src/mark.rs` | ход значков: знак-камертон и колонка — чистые машины состояний на `anvil_ui::motion::machine` |
| `src/mark_render.rs` | кадр знака и колонки в RGBA без сторонних крейтов: подвыборки, контур плитки многоугольником |
| `src/flyout.rs` | окно микшера и `Shared` — открыть/закрыть из потока трея |
| `src/placement.rs` | где поставить окно: у значка, к панели задач, в рабочей области |
| `src/icons.rs` | значки программ из exe, «динамик» линиями |
| `src/sys.rs` | Win32: один экземпляр, консоль, монитор и масштаб, показ окна, тема панели задач, значки из RGBA |
| `src/texts.rs` | строки RU/EN |
| `src/cli.rs` | командная строка `--set`/`--mute`/`--get`: разбор ключей, поиск цели в снимке, расчёт новых значений — чистые функции |
| `src/contrast.rs` | высокий контраст Windows: чтение цветов системы, палитра окна (при включении подменяет палитру набора — `set_palette_override`) |
| `src/rules.rs` | потолок громкости и правила по программам — чистые функции: что сделать по снимку и событиям |
| `src/duck.rs` | автоприглушение — машина состояний без часов и Windows: время и пики приходят аргументами |
| `src/snap.rs` | снимок окна в PNG для проверки (`KAMERTON_SNAP`) |
| `build.rs` | значок exe и сведения о файле — ресурс из `assets/icon/kamerton.ico` (`winresource`) |
| `assets/icon` | файлы знака: SVG, PNG, `.ico`, образцы RGBA для тестов (`scripts/render-icon.ps1`) |

**Цвет знака** — `tray_color` из «Настроек»: трей, знак в «О программе» и значок окна микшера
(`sys::set_window_icon`). Окно микшера — отдельный процесс: цвет перечитывается из `settings.txt`, когда окно
получает фокус (`Flyout::follow_icon_color`). Значок exe — ресурс, всегда пурпур.

**Значок в трее.** На каждый `refresh` ядра трей берёт устройство вывода по умолчанию и передаёт обеим
сценам (`mark::MarkScene`, `mark::SpeakerScene`) громкость, «без звука», ошибку и смену устройства. Показ —
`motion::machine::Presenter` набора: пока сцена движется, кадр не чаще 10 раз в секунду по таймеру
`MARK_TIMER`; когда стоит — один кадр на каждую смену вида. Кадр рисует `mark_render`, `sys::icon_from_rgba`
делает из него `HICON` для `NIM_MODIFY`, после — `DestroyIcon`. Числа и ход — эталон `reference/mark-motion.html` изменения OpenSpec `stage-0-9-mark-motion` (`openspec/changes/`, после архивации — `openspec/changes/archive/`).
Ошибка (красное) — снимок без устройства вывода по умолчанию или `snapshot()` с ошибкой (поток звука
остановлен). При остановке службы Windows ядро пробует пересоздаться; не вышло — остаётся прежнее со
старым списком, и значок краснеет, только если Windows убрала устройства (живой проверки нет).

## Процессы и потоки

Один процесс (`kamerton` без ключей; второй экземпляр выходит — мьютекс `Local\Kamerton`):

- **main** — цикл окна микшера и рисовальщик D3D11 — крейт набора `anvil-d3d` (с 1.3.11; раньше своя копия `shell.rs` и `d3d.rs`). Окно
  создаётся при старте за экранами, под плащом DWM (`DWMWA_CLOAK`): первый кадр рисуется целиком — прогрев
  значков программ, шрифтов и текстур, — после чего окно прячется. Пока окно закрыто, кадров нет.
- **audio** — ядро звука, общее для значка и окна; будит трей (`tray::refresh`) и окно (`request_repaint`).
- **tray** — невидимое окно сообщений: значок, меню, хук колеса.

Открытие (`flyout::Shared`, как у EarTrumpet): щелчок по значку → трей кладёт место значка и показывает
окно без фокуса под плащом (`SW_SHOWNOACTIVATE`) и шлёт `WM_PAINT` (`InvalidateRect`: побудка egui
спрятанному окну может не дойти) → кадр: окно встаёт на место (`placement::place`) и рисуется →
сразу после `Present` плащ снимается и окно берёт фокус. Замер: 9–10 мс от щелчка до видимого окна
(первое открытие после старта), 5–6 мс — дальше.

Состояния: спрятано → открывается → открыто. Щелчок в «открывается» ничего не делает; в «открыто» —
закрывает; в «спрятано» — открывает, но не раньше 300 мс после закрытия (окно закрылось от этого же
щелчка — потеряло фокус). Закрытие (потеря фокуса, Esc, повторный щелчок, Alt+F4) — под плащ и
`SW_HIDE`. «Выход» в меню (или `WM_CLOSE` окну трея, `scripts/quit.ps1`) убирает значок и закрывает окно
по-настоящему.

`kamerton --flyout [l,t,r,b] [--passive]` — то же окно отдельным процессом со своим ядром звука, для
проверки вида; закрытие окна — выход.

## Поток звука

`Audio::start` поднимает поток `audio` (COM в режиме MTA) и возвращает первый снимок; `start_quiet` — то
же без очереди событий (окно спрашивает снимок само, пока видно). Все объекты Core Audio живут только в
этом потоке. Наружу:

- `audio.events()` — события по порядку (`Event`); консоль держит свою копию `Snapshot` и
  применяет к ней события (`Snapshot::apply`).
- `Control` (из `audio.control()`, копируется в любой поток): `set_volume`, `set_muted` — громкость 0..1
  и «без звука» устройству или программе (всем её сессиям), ошибка `NotFound`, если цели уже нет;
  `adjust_default` — сдвиг громкости устройства вывода по умолчанию (колесо над значком); `snapshot` —
  снимок «как сейчас»; `peaks` — пиковые уровни 0..1, читаются только при вызове.
- Удаление `Audio` останавливает поток: подписки снимаются, затем `CoUninitialize`.

## Окно

- Размер: ширина 360, высота по содержимому (`flyout::content_height`), не выше рабочей области.
- Место: `placement::place` по прямоугольнику значка (`Shell_NotifyIconGetRect`), рабочей области
  монитора и стороне панели задач (`placement::taskbar_edge`), в физических пикселях с масштабом монитора.
- Углы — регион окна (`SetWindowRgn`), окно непрозрачное.
- Колесо над значком — низкоуровневый хук мыши: сравнивает курсор с прямоугольником значка (его
  запоминают, когда курсор над значком) и шлёт шаг в окно трея; колесо над значком поглощается.

## События Windows → события Kamerton

1. Обратные вызовы Windows только шлют метку в канал потока:
   - устройство подключено, отключено, сменило состояние, сменилось устройство по умолчанию, имя
     устройства (`IMMNotificationClient`) → «перечитать устройства»;
   - громкость устройства (`IAudioEndpointVolumeCallback`), громкость, имя, состояние сессии, сессия
     отключена (`IAudioSessionEvents`) → «перечитать устройство X»;
   - новая сессия → сама сессия (Windows отдаёт её в уведомлении) + «перечитать устройство X»;
   - завершился процесс программы (ожидание на его дескрипторе) → «перечитать программы».
2. Поток склеивает метки, пока они идут чаще 30 мс, но не дольше 100 мс; широкое перечитывание
   поглощает узкие.
3. Перечитывает нужное, строит новый снимок и сравнивает с прошлым (`model::diff`); наружу уходят
   только настоящие изменения, ровно одним событием каждое.

Таймеров нет: в тишине поток спит на канале.

## Почему список сессий не перебирается заново

Каждый перебор списка сессий Windows (`GetSessionEnumerator`), пока у программы на руках объекты
сессий, оставляет в её памяти ~450 байт на каждую сессию, и Windows их не возвращает (замер
22.10.2026: ~5 КБ на проход по всем устройствам, ~26 КБ на каждый короткий процесс со звуком).
Поэтому:

- список перебирается один раз — при открытии устройства;
- новые сессии берутся из уведомления `OnSessionCreated`;
- прежние сессии перечитываются через свои объекты (состояние, имя, громкость), ушедшие — убираются.

## Программы

- Сессии одного exe на одном устройстве — одна программа. Ключ — путь exe в нижнем регистре и id
  устройства; системные звуки — `system`; процесс, путь которого прочитать нельзя, — `pid:<n>`.
- Имя: из сессии (`GetDisplayName`, кроме ссылок «@…»), иначе описание файла exe, иначе имя exe. Процесс,
  который не открыть даже с `PROCESS_QUERY_LIMITED_INFORMATION` (служба, защищённый), назван по имени
  exe из идентификатора сессии (`…|\Device\…\app.exe%b…`, `model::exe_from_session`). Не вышло и это —
  имя пустое: окно пишет «Неизвестная программа» и мелко «PID <n>», `--list` — `?`.
- Громкость программы — у самой громкой её сессии; «без звука» — когда молчат все.
- Скрыты сессии в состоянии «expired» и сессии завершившихся процессов.
- Описания файлов кешируются по пути на время работы.

## Рисовальщик D3D11 (крейт `anvil-d3d`)

Крейт набора, описание — `Anvil/docs/D3D.md`; Kamerton берёт его по тегу `kit-v0.9.1`. Что делает рисовальщик:

- Устройство D3D11 (уровень 11_0), цепочка кадров flip-discard, B8G8R8A8; размер буферов подгоняется к
  окну на каждом кадре, где он изменился.
- Один шейдер (компилируется при запуске `D3DCompile`): вершина egui (точки, uv, цвет) → экран; цвет ×
  текстура. Цвета egui — sRGB с умноженной альфой, смешивание в гамме (ONE / INV_SRC_ALPHA), текстуры
  R8G8B8A8_UNORM — как у egui_glow.
- Все сетки кадра — в одни динамические буферы; рисуются кусками со своими ножницами и текстурой.
- Снимок кадра (`ViewportCommand::Screenshot`) — копия заднего буфера до `Present`, приходит в egui
  событием `Event::Screenshot`.
- Кадры — только по запросу egui (`set_request_repaint_callback` будит цикл winit); в покое цикл спит.

## Устройства и маршруты (этап 0.3)

- Устройство по умолчанию — `IPolicyConfig::SetDefaultEndpoint` (COM, CLSID `870AF99C-…`), так делает
  панель «Звук»: «по умолчанию» — роли console, multimedia и communications; «для связи» — только
  communications. В снимке у устройства — `is_default` (console) и `is_comm` (communications).
- Перенос программы — WinRT-фабрика `Windows.Media.Internal.AudioPolicyConfig`
  (`RoGetActivationFactory`); IID у сборок Windows разный — пробуем `ab3d4648-…`, затем `2a59116d-…`.
  `SetPersistedDefaultAudioEndpoint(pid, направление, роль, id)` для console и multimedia всем процессам
  программы; пустой id — «как в системе». Id устройства в этом API —
  `\\?\SWD#MMDEVAPI#<id>#{e6327cad-…}` (вывод) / `#{2eef81be-…}` (запись).
- Закрепление (`App::pinned`) читается `GetPersistedDefaultAudioEndpoint` один раз на процесс (кеш по
  pid и направлению) и после переноса. Фабрики нет — `Snapshot::can_route = false`, перенос в окне
  недоступен с пояснением.
- Закрепление Windows живёт, пока жив процесс. Выбор владельца (меню строки, перетаскивание —
  `Flyout::move_app`) пишется в `Settings::app_routes` (`approute=<exe>|<id устройства>`); на `AppAdded`
  без закрепления `profiles::react` отдаёт `Cmd::Move` на запомненное устройство, если оно есть в снимке.
- Список устройств: если устройство из `EnumAudioEndpoints` не открылось (только что включено, Bluetooth и
  т. п.), `rescan_devices` возвращает `true`, и поток звука перечитывает список ещё до 8 раз с паузой 1,5 с
  (`DEVICE_RETRIES`, `DEVICE_RETRY` в `audio/mod.rs`). Раньше такое устройство появлялось только после
  смены устройства по умолчанию.
- Сочетания громкости устройства: `Settings::device_vol_hotkeys` (`devvolkey.<действие>.<id>`),
  `tray::Bound::DeviceVolume` шагает громкость любого устройства вывода из снимка и показывает плашку.
  Медиа-клавиши громкости — `hotkeys::Media` (`Combo::media`, VK 0xAD–0xAF, нужен модификатор);
  egui их не знает, поэтому цикл окна (`shell::note_media_key`) запоминает нажатие, а `Flyout::capture_keys`
  забирает его (`hotkeys::take_media`).
- Всё недокументированное — только в `policy.rs`; ошибка отключает свою функцию, а не программу.
- Перенесённая программа оставляет на прежнем устройстве неактивную сессию (Windows убирает её только
  при выходе программы). Снимок прячет её (`model::moved_away`): сессия молчит, программа закреплена за
  другим устройством (не закреплена — за устройством по умолчанию) и там у неё уже есть сессия. Пока на
  новом устройстве сессии нет, строка остаётся на старом — программа не пропадает совсем.

## Горячие клавиши (этап 0.4)

- Настройки общие у окна и трея: `flyout::Shared::settings`. Окно пишет (страница «Горячие клавиши»),
  трей регистрирует: `RegisterHotKey(окно трея, id, модификаторы | MOD_NOREPEAT, код)` для каждого
  сочетания; результат («свободно»/«занято») — `Shared::hotkey_free` по ключу из `settings.txt`.
- Окно поменяло сочетание или начало запись — `tray::reload_hotkeys()` (сообщение окну трея): трей
  снимает все и регистрирует заново. Пока окно записывает сочетание (`Shared::capturing`), трей не
  держит ни одного — иначе нажатие ушло бы ему, а не окну.
- `WM_HOTKEY` → действие в потоке трея через `Control`: громкость устройства по умолчанию, «без звука»,
  следующее устройство (`hotkeys::next_output`), окно (`Shared::toggle` у значка). Действия программы —
  по всем её сессиям на устройствах вывода (`tray::apps_with_exe`); «без звука» — хоть одна звучит →
  заглушить все, иначе включить все.

## Профили и память (этап 0.5)

- Решения — `profiles.rs`, без Windows: `capture` (профиль из снимка), `apply` (команды и память),
  `react` (по событиям: память громкости, громкость новых программ, профиль по правилу подключения).
- Делает трей: на каждый `refresh` ядра берёт снимок, считает разницу с прошлым (`model::diff`) и
  отдаёт события `react`; команды выполняет через `Control` (`tray::run_cmds`). Память меняется часто —
  записывается таймером через 2 с после изменения и при выходе. Свои же команды возвращаются событиями
  и только подтверждают память.
- Применить профиль — `tray::run_profile` (из меню значка, со страницы «Профили», по правилу).

## Настройки, окно микшера, баланс (этап 0.6)

- Тема и язык из `settings.txt` (`theme`, `lang`); `KAMERTON_THEME`/`KAMERTON_LANG` важнее — для снимков.
  Смена на странице — сразу: `anvil_ui::choose`, `texts::apply` и язык набора.
- Скрытое — `hidden_apps`/`hidden_devices`; окно и микшер рисуют `Shared::visible` (снимок без скрытого,
  `model::visible`), меню значка пропускает скрытые устройства.
- Шкала — `model::to_pos`/`from_pos` (квадрат); ползунок узнаёт о ней из данных контекста egui.
- Анимация — `Flyout::layout` со сдвигом от края панели задач, кривая `motion::curve::ease_out` набора,
  флаг Windows — `motion::pref::animations_enabled`.
- Колесо вне окна — тот же хук трея: окно открыто (`Shared::is_open`) и флаг `Shared::wheel_outside`
  (копия настройки без блокировки), курсор вне `GetWindowRect` окна → шаг, колесо поглощается.
- Окно микшера — процесс `kamerton --mixer` (мьютекс `Local\KamertonMixer`; второй находит окно по
  заголовку и выводит наверх), тот же `Flyout` в режиме `mixer`: обычное окно `shell::Config` с рамкой,
  колонки `MIXER_COLUMN` = 340. Место и размер — `mixer_rect` при закрытии.
- Баланс — `IAudioEndpointVolume`: у двухканальных устройств `GetChannelVolumeLevelScalar(0|1)` →
  `model::balance_of`; установка — `model::channels_for` → `SetChannelVolumeLevelScalar`.

## Надёжность (этап 0.7)

- Сброс ядра: после каждого пересмотра поток звука спрашивает `Engine::healthy` (перечислитель и
  громкость устройств отвечают). Код ошибки из `win::needs_reset` (AUDCLNT_E_DEVICE_INVALIDATED,
  AUDCLNT_E_SERVICE_NOT_RUNNING, RPC_E_DISCONNECTED, RPC_S_SERVER_UNAVAILABLE, RPC_S_CALL_FAILED) —
  ядро создаётся заново; не вышло — повтор раз в 2 с. Снимок прошлого ядра остаётся, поэтому события
  после сброса — только по разнице.
- `Msg::Reset` (`Control::reset`) — то же по просьбе: трей шлёт его на `WM_WTSSESSION_CHANGE`
  (подключение к консоли или удалённому столу, разблокировка).
- Окно запоминает, куда его поставили; если Windows сама сменила размер или место (смена масштаба),
  на следующем кадре окно ставится заново.
- Паника пишется строкой в `%APPDATA%\Kamerton\crash.log`: время Unix, версия, место, сообщение.

## Плашка громкости, высокий контраст, командная строка (этап 1.0)

- **Плашка** — то же окно egui, что и окно микшера, а не второе: состояние `Shared::state = OSD`. Трей после
  изменения громкости устройства по умолчанию (колесо, средний щелчок, «Громче», «Тише», «Без звука»; для колеса и
  сочетаний — новая громкость из ответа `adjust_default`) зовёт `Shared::show_osd(значок, громкость, без звука)`:
  выключено (`osd=0`), окно открыто или открывается — ничего; иначе кладёт `OsdInfo` (до какого времени
  держать — 1,5 с) и из `HIDDEN` показывает окно под плащом без фокуса (`SW_SHOWNOACTIVATE`) и шлёт `WM_PAINT`,
  как при открытии окна. Первый кадр `Flyout::osd_ui`: место (`placement::place_osd` — по центру рабочей
  области, у стороны панели задач, `OSD_GAP` 24), размер 260 × 56 (с масштабом монитора), углы регионом,
  `WS_EX_NOACTIVATE` (`sys::set_no_activate`); после `Present` плащ снимается (`after_present`). Появление —
  сдвиг на 8 px к месту за `SLIDE_SECS` (если анимация включена и не выключена в Windows). Время вышло —
  `hide_osd`: плащ, `SW_HIDE`, `HIDDEN`. Щелчок по значку в состоянии `OSD` открывает окно микшера
  (`Shared::toggle` → `open`, который сбрасывает плашку, а первый кадр открытия снимает `NOACTIVATE`).
- **Высокий контраст** — `contrast::follow` в начале каждого кадра окна читает настройку Windows
  (`SPI_GETHIGHCONTRAST`, цвета `GetSysColor`); изменилось — подменяет палитру набора системной
  (`anvil_ui::theme::set_palette_override`; стиль egui пересобирается из неё, тема = по яркости фона) или снимает подмену.
  Свои части окна и виджеты набора (переключатели и др.) берут одну палитру — `contrast::palette` = `Palette::of_ctx`.
- **Поиск по «Настройкам»** был (1.0–1.3.8) и убран в 1.3.9 по слову владельца (модуль `settings_search` удалён).
- **Командная строка** — `main.rs::run_command`: `Audio::start` (своё ядро звука), `cli::find` по снимку,
  `Control::set_volume` / `set_muted`; код выхода — по `cli::CliError`.

## Потолок, приглушение, правила (этап 1.1)

- **Потолок.** `tray::react_to_changes` после каждого пересмотра ядра (и при запуске — трей сам шлёт первый `refresh`)
  берёт снимок и зовёт `rules::limit_cmds`: устройство вывода по умолчанию выше общего потолка и программы выше своего —
  `Cmd::SetDeviceVolume` / `Cmd::SetVolume` на потолок; свои команды возвращаются событиями с верной громкостью —
  цикла нет.
- **Правила.** Там же, после памяти и профилей: `rules::rule_cmds(события, снимок, правила)` — по `AppAdded` (условие
  верно сейчас) и `DeviceAdded` (программа уже играет). Команды — те же `Cmd` (`Move`, `SetVolume`, `SetMuted`).
- **Приглушение.** `duck::Ducker` живёт в потоке трея (`DUCKER`); таймер `DUCK_TIMER` (250 мс) стартует в
  `sync_duck`, когда включено приглушение и выбраны главные, и гасится, когда нет (тогда `release_all` возвращает
  громкость). Шаг `duck_tick`: снимок + `Control::peaks` по программам → `Ducker::tick` → команды. События
  приглушённых программ (`Ducker::is_ducked`) вырезаются из потока для `profiles::react`, чтобы приглушённая громкость
  не попала в память. На `WM_DESTROY` трей возвращает приглушённое до выхода.

## Ночной режим (этап 1.2)

- `rules::device_cap(дневной, ночной, сейчас)` — итоговый потолок общей громкости: в часы ночи (`rules::in_window`,
  минуты от полуночи, местное время из `sys::local_minutes` — `GetLocalTime`) меньший из дневного и ночного, иначе дневной.
  `tray::react_to_changes` передаёт его в `rules::limit_cmds`; чтобы граница часов заметилась в тишине, минутный таймер
  трея (`UPDATE_TIMER`, он же проверяет обновления) шлёт и `refresh`.
- «Окно микшера поверх всех»: `main::run_mixer` берёт `mixer_on_top` из настроек для `shell::Config::always_on_top`.
