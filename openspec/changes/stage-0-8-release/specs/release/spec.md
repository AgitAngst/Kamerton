## Purpose

Готовая к скачиванию сборка Kamerton: переносной архив по соглашению выпусков Anvil, понятное место
настроек, версия на виду.

## ADDED Requirements

### Requirement: Переносной режим
Если рядом с `kamerton.exe` лежит `settings.txt`, программа SHALL читать и писать настройки и `crash.log`
в папке exe; иначе — в `%APPDATA%\Kamerton`.

#### Scenario: Копия на флешке
- **WHEN** рядом с exe лежит `settings.txt`
- **THEN** изменения настроек пишутся в этот файл, а в «О программе» видна пометка переносной копии

### Requirement: Версия на виду
Страница «Настройки» SHALL показывать раздел «О программе» с версией программы.

#### Scenario: Какая у меня версия
- **WHEN** пользователь открывает страницу «Настройки»
- **THEN** внизу написано «Kamerton X.Y.Z»

### Requirement: Выпуск по тегу
Сборка выпуска SHALL запускаться только тегом `vX.Y.Z` и давать `kamerton-X.Y.Z-windows-x64.zip` с exe
в корне и `SHA256SUMS`; при заведённом сертификате exe подписывается до упаковки.

#### Scenario: Тег поставлен
- **WHEN** владелец ставит тег `v1.0.0`
- **THEN** в GitHub Release появляются архив и `SHA256SUMS` с его суммой

### Requirement: Обновления изнутри программы
Трей SHALL проверять выпуски на GitHub при запуске и раз в сутки, если включено «Проверять обновления»;
новая версия SHALL предлагаться в «Настройки → О программе» и в меню значка, ставиться только после сверки
SHA-256 и включаться перезапуском; пропущенная версия сама не предлагается.

#### Scenario: Вышла новая версия
- **WHEN** в GitHub Releases появился выпуск новее текущего
- **THEN** в меню значка есть «Обновить до X.Y.Z», после скачивания — «Перезапустить на X.Y.Z»
