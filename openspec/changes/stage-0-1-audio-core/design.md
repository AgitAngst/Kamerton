## Context

Зачем — proposal.md. Кода звука в Kamerton пока нет; интерфейса тоже нет, поэтому ядро должно
проверяться из консоли.

## Goals / Non-Goals

**Goals:** одна точка правды о звуке, которую окно этапа 0.2 будет только читать; ноль работы, когда
ничего не меняется.

**Non-Goals:** смена устройства по умолчанию и перевод программы на другое устройство (этап 0.3);
логарифмическая шкала (0.6); сохранение громкости программ (0.5).

## Decisions

1. **Свой поток звука.** Все COM-объекты живут в одном потоке (MTA), остальная программа говорит с ним
   через каналы: команды туда, снимки и события обратно. *Иначе:* COM в потоке окна — тогда eframe и
   обратные вызовы Windows делят один поток и тормозят друг друга; объекты Core Audio к тому же не
   переносимы между потоками без маршалинга.
2. **События только будят.** Обратные вызовы Windows (`IMMNotificationClient`,
   `IAudioSessionNotification`, `IAudioSessionEvents`, `IAudioEndpointVolumeCallback`) ничего не
   читают сами — кладут короткую метку в канал потока звука, и тот перечитывает затронутое устройство.
   Повторные метки за 30 мс склеиваются. *Иначе:* читать прямо в обратном вызове — Windows запрещает
   долгие вызовы там и может зависнуть.
3. **Снимок + разница.** Поток держит модель (устройства → программы) и после каждого перечитывания
   сравнивает её с прошлой; наружу идут события `Added/Removed/Changed`. Сравнение — чистая функция без
   COM, её покрывают тесты. *Иначе:* слать сырые события Windows — они дублируются и приходят не по
   порядку (как раз причина «пропадающих программ» в EarTrumpet).
4. **Программа = исполняемый файл на устройстве.** Сессии одного exe на одном устройстве
   (Chrome, Discord — много процессов) сливаются в одну программу; громкость и «без звука»
   ставятся всем её сессиям. Системные звуки — отдельная программа с флагом. Имя: `DisplayName`
   сессии, иначе описание файла, иначе имя exe. Ключ — путь exe в нижнем регистре + id устройства.
5. **Уровни по запросу.** `IAudioMeterInformation` читается только когда кто-то просит (окно открыто
   или `--watch --peaks`), без таймера в самом ядре.
6. **Освобождение.** Ушедшие сессии и устройства снимаются с подписки (`UnregisterAudioSessionNotification`
   и т. п.) в том же перечитывании; тест счётчика подписок в `--watch` следит, что они не копятся.

## Risks / Trade-offs

- [Сессии в состоянии «expired» висят часами] → прятать сессии `AudioSessionStateExpired` и
  программы без живого процесса.
- [Доступ к пути exe чужого процесса закрыт (службы, игры с античитом)] → `PROCESS_QUERY_LIMITED_INFORMATION`,
  при отказе — имя из сессии или `pid <n>`.
- [Двойные обратные вызовы и гонки при выключении] → поток звука выходит по команде `Quit`, сначала
  снимает все подписки, потом `CoUninitialize`.
