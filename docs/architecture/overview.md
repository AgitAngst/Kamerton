# Как устроено

## Части

| Файл | Что делает |
|---|---|
| `src/main.rs` | разбор ключей: без ключей — трей, `--flyout` — окно микшера, остальное — консольные режимы |
| `src/audio/mod.rs` | `Audio`, `Control`: поток звука, каналы команд и событий, склейка меток |
| `src/audio/win.rs` | COM: Core Audio, подписки на события Windows, слежение за процессами |
| `src/audio/model.rs` | модель без COM: устройства, программы, события, разница снимков, шаг громкости |
| `src/ipc.rs` | канал `\\.\pipe\kamerton-ipc` для Antresol: разбор запросов, сбор ответов, поток сервера |
| `src/tray.rs` | поток трея: значок, подсказка, щелчок, меню, хук колеса |
| `src/flyout.rs` | окно микшера и `Shared` — открыть/закрыть из потока трея |
| `src/shell.rs` | цикл окна: winit + egui-winit, кадры по запросу egui, снимок |
| `src/d3d.rs` | рисовальщик egui на Direct3D 11: шейдер, буферы, текстуры, ножницы |
| `src/placement.rs` | где поставить окно: у значка, к панели задач, в рабочей области |
| `src/icons.rs` | значки программ из exe, «динамик» линиями |
| `src/sys.rs` | Win32: один экземпляр, консоль, монитор и масштаб, показ окна, тема панели задач |
| `src/texts.rs` | строки RU/EN |
| `src/snap.rs` | снимок окна в PNG для проверки (`KAMERTON_SNAP`) |

## Процессы и потоки

Один процесс (`kamerton` без ключей; второй экземпляр выходит — мьютекс `Local\Kamerton`):

- **main** — цикл окна микшера (`shell.rs`: winit + egui-winit) и рисовальщик D3D11 (`d3d.rs`). Окно
  создаётся при старте за экранами, под плащом DWM (`DWMWA_CLOAK`): первый кадр рисуется целиком — прогрев
  значков программ, шрифтов и текстур, — после чего окно прячется. Пока окно закрыто, кадров нет.
- **audio** — ядро звука, общее для значка и окна; будит трей (`tray::refresh`) и окно (`request_repaint`).
- **tray** — невидимое окно сообщений: значок, меню, хук колеса.
- **ipc** — сервер именованного канала для Antresol (см. «Связь с Antresol» ниже); на каждое подключение
  короткий поток `ipc-client`.

Открытие (`flyout::Shared`, как у EarTrumpet): щелчок по значку → трей кладёт место значка и показывает
окно без фокуса под плащом (`SW_SHOWNOACTIVATE`) и шлёт `WM_PAINT` (`InvalidateRect`: побудка egui
спрятанному окну может не дойти) → кадр: окно встаёт на место (`placement::place`) и рисуется →
сразу после `Present` плащ снимается и окно берёт фокус. Замер: 9–10 мс от щелчка до видимого окна
(первое открытие после старта), 5–6 мс — дальше.

Состояния: спрятано → открывается → открыто. Щелчок в «открывается» ничего не делает; в «открыто» —
закрывает; в «спрятано» — открывает, но не раньше 300 мс после закрытия (окно закрылось от этого же
щелчка — потеряло фокус). Закрытие (потеря фокуса, Esc, повторный щелчок, Alt+F4) — под плащ и
`SW_HIDE`. «Выход» в меню (или `WM_CLOSE` окну трея, `scripts/quit.ps1`) убирает значок и закрывает окно
по-настоящему.

`kamerton --flyout [l,t,r,b] [--passive]` — то же окно отдельным процессом со своим ядром звука, для
проверки вида; закрытие окна — выход.

## Поток звука

`Audio::start` поднимает поток `audio` (COM в режиме MTA) и возвращает первый снимок; `start_quiet` — то
же без очереди событий (окно спрашивает снимок само, пока видно). Все объекты Core Audio живут только в
этом потоке. Наружу:

- `audio.events()` — события по порядку (`Event`); консоль держит свою копию `Snapshot` и
  применяет к ней события (`Snapshot::apply`).
- `Control` (из `audio.control()`, копируется в любой поток): `set_volume`, `set_muted` — громкость 0..1
  и «без звука» устройству или программе (всем её сессиям), ошибка `NotFound`, если цели уже нет;
  `adjust_default` — сдвиг громкости устройства вывода по умолчанию (колесо над значком); `snapshot` —
  снимок «как сейчас»; `peaks` — пиковые уровни 0..1, читаются только при вызове.
- Удаление `Audio` останавливает поток: подписки снимаются, затем `CoUninitialize`.

## Связь с Antresol

Поток `ipc` по кругу создаёт экземпляр канала `\\.\pipe\kamerton-ipc` (байтовый, ожидающий; удалённые
клиенты отклонены; самый первый экземпляр — с `FILE_FLAG_FIRST_PIPE_INSTANCE`, чтобы чужой процесс не
занял имя), ждёт клиента и отдаёт его потоку `ipc-client` (не больше 8 разом, остальные закрываются).
Тот ждёт строку запроса опросом `PeekNamedPipe` не дольше ~1 с (иначе молчащий клиент завесил бы поток),
отвечает и закрывает канал. Протокол — [Как пользоваться](../guide/usage.md#связь-с-antresol).

- `ipc::parse` → `Request`; `ipc::resolve` (запрос + `Snapshot` → `Action` над устройством по умолчанию
  или его программой); `ipc::format_state`, `format_err` — чистые функции, под тестами. Звук меняется
  через `audio::Control` (`snapshot`, `set_volume`, `set_muted`), как из окна.
- `open`: поток канала шлёт `WM_APP+4` окну трея (`tray::open_flyout`), поток трея зовёт
  `Shared::show` — спрятано → открыть у значка (как щелчком), иначе ничего.
- Ошибки Win32 в канале (занято имя, отказ создания) не роняют программу: сервер ждёт 2 с и пробует снова.

## Окно

- Размер: ширина 360, высота по содержимому (`flyout::content_height`), не выше рабочей области.
- Место: `placement::place` по прямоугольнику значка (`Shell_NotifyIconGetRect`), рабочей области
  монитора и стороне панели задач (`placement::taskbar_edge`), в физических пикселях с масштабом монитора.
- Углы — регион окна (`SetWindowRgn`), окно непрозрачное.
- Значок в трее — глиф Segoe Fluent Icons (Windows 11) или Segoe MDL2 Assets (Windows 10), нарисованный
  GDI; яркость глифа становится прозрачностью, цвет — по `SystemUsesLightTheme`.
- Колесо над значком — низкоуровневый хук мыши: сравнивает курсор с прямоугольником значка (его
  запоминают, когда курсор над значком) и шлёт шаг в окно трея; колесо над значком поглощается.

## События Windows → события Kamerton

1. Обратные вызовы Windows только шлют метку в канал потока:
   - устройство подключено, отключено, сменило состояние, сменилось устройство по умолчанию, имя
     устройства (`IMMNotificationClient`) → «перечитать устройства»;
   - громкость устройства (`IAudioEndpointVolumeCallback`), громкость, имя, состояние сессии, сессия
     отключена (`IAudioSessionEvents`) → «перечитать устройство X»;
   - новая сессия → сама сессия (Windows отдаёт её в уведомлении) + «перечитать устройство X»;
   - завершился процесс программы (ожидание на его дескрипторе) → «перечитать программы».
2. Поток склеивает метки, пока они идут чаще 30 мс, но не дольше 100 мс; широкое перечитывание
   поглощает узкие.
3. Перечитывает нужное, строит новый снимок и сравнивает с прошлым (`model::diff`); наружу уходят
   только настоящие изменения, ровно одним событием каждое.

Таймеров нет: в тишине поток спит на канале.

## Почему список сессий не перебирается заново

Каждый перебор списка сессий Windows (`GetSessionEnumerator`), пока у программы на руках объекты
сессий, оставляет в её памяти ~450 байт на каждую сессию, и Windows их не возвращает (замер
22.10.2026: ~5 КБ на проход по всем устройствам, ~26 КБ на каждый короткий процесс со звуком).
Поэтому:

- список перебирается один раз — при открытии устройства;
- новые сессии берутся из уведомления `OnSessionCreated`;
- прежние сессии перечитываются через свои объекты (состояние, имя, громкость), ушедшие — убираются.

## Программы

- Сессии одного exe на одном устройстве — одна программа. Ключ — путь exe в нижнем регистре и id
  устройства; системные звуки — `system`; процесс, путь которого прочитать нельзя, — `pid:<n>`.
- Громкость программы — у самой громкой её сессии; «без звука» — когда молчат все.
- Скрыты сессии в состоянии «expired» и сессии завершившихся процессов.
- Описания файлов кешируются по пути на время работы.

## Рисовальщик D3D11

- Устройство D3D11 (уровень 11_0), цепочка кадров flip-discard, B8G8R8A8; размер буферов подгоняется к
  окну на каждом кадре, где он изменился.
- Один шейдер (компилируется при запуске `D3DCompile`): вершина egui (точки, uv, цвет) → экран; цвет ×
  текстура. Цвета egui — sRGB с умноженной альфой, смешивание в гамме (ONE / INV_SRC_ALPHA), текстуры
  R8G8B8A8_UNORM — как у egui_glow.
- Все сетки кадра — в одни динамические буферы; рисуются кусками со своими ножницами и текстурой.
- Снимок кадра (`ViewportCommand::Screenshot`) — копия заднего буфера до `Present`, приходит в egui
  событием `Event::Screenshot`.
- Кадры — только по запросу egui (`set_request_repaint_callback` будит цикл winit); в покое цикл спит.
