# Kamerton — передача дел

Обновлено 22.10.2026. Версия 0.1.0, этап 0.1 «Ядро звука» закрыт (изменение OpenSpec в архиве).
Следующий — этап 0.2 «Трей и выпадающее окно» (SPEC.md).

## Где мы

- Ядро звука (`src/audio/`): устройства, программы, события без опроса, уровни по запросу, команды
  громкости и «без звука». Консоль: `--list`, `--watch [--peaks] [--for <s>]`.
- `checks.py fmt test clippy` зелёные на ПК (11 тестов). CI не запускался.
- Вживую: `--list` совпадает с устройствами ПК, `--peaks` показывает уровень играющей программы,
  события программ приходят; события устройств (наушники, ползунок Windows) владелец проверил 22.10 — «работает».
- Утечка памяти найдена и починена (22.10): ~26 КБ на каждый короткий процесс со звуком. Причина —
  повторный перебор списка сессий Windows: пока на руках объекты сессий, каждый перебор оставляет
  ~450 байт на сессию. Теперь перебор только при открытии устройства, новые сессии — из уведомления
  `OnSessionCreated`. После починки на 120 процессах память стоит (2,18→2,45→2,39→2,39 МБ). Подробно —
  `docs/architecture/overview.md`; как повторить — `docs/dev/development.md` и `scripts/leak-burst.ps1`.

## Решения

- Kamerton самостоятельный: код других проектов владельца не читается и не копируется.
- Программа = exe на устройстве; pid сортируются, иначе каждое перечитывание давало ложную «смену».
- Конец процесса ловится ожиданием на его дескрипторе (`RegisterWaitForSingleObject`), не опросом.
- Список сессий не перебирается повторно (см. выше).
- Тесты утечки грузят ПК — гонять только с согласия владельца.
